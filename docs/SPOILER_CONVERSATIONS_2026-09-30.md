# Spoiler 대화방 분류 및 내·상대 메시지 통합

2026-09-30 후속 요청: 발화자별 분류를 대화방별 분류로 바꾸고, 단톡방에서도 내 메시지와 여러 참여자 메시지의 상호작용을 시간순으로 표시한다.

## 원인

지난 GUI 변경은 새 기록의 `ChatId`로 방을 묶었으나 이전 본문에 남은 작성자별 `GroupKey`를 실제 방 ID로 보완하지 않았다. 따라서 저장돼 있던 옛 기록은 여전히 작성자별 목록에 남았다. 또한 다른 기기에서 보낸 내 메시지가 실시간 MSG로 전달되지 않는 경우를 연결 중에 보충하지 않았다. 실시간 최대 로그를 복구 기준점으로만 쓰면 그보다 앞의 누락된 내 메시지를 건너뛸 수 있었다.

## 수정

- 같은 계정의 암호화 문서에 남아 있는 실제 방·작성자 ID로 옛 그룹 해시를 재계산한다. 정확히 일치하는 기록만 방 ID를 복원한다. 이름이나 메시지 ID만으로 서로 다른 방을 합치지 않는다.
- 정확히 방을 확인한 기록은 내·상대 메시지를 구분해 같은 방에 표시한다. 방 제목이 없으면 그 방에서 관측한 상대 작성자 이름들을 사용하고 마지막 발화자 때문에 방 이름이 바뀌지 않도록 한다. 내 메시지만 있으면 중립적인 방 ID를 표시한다.
- 확인할 근거가 없는 기록은 **방 미확인 이전 기록**으로 분리한다. 이 영역을 실제 카카오톡 대화방처럼 취급하거나 답장 대상으로 사용하지 않는다.
- **내 메시지 포함**은 기본으로 켠다. 원문 타임라인은 서버 시각, 같은 시각에서는 숫자 메시지 ID 순으로 표시한다.
- 연결 중 알려진 방의 내역을 읽기 전용으로 보충한다. 내·상대 메시지를 작성자 필터 없이 수집한다. 실시간 최대 로그와 별개로 검증한 페이지 순서에 따라 동기화 진행점을 유지한다.
- 재접속 시 보관 중인 방의 가장 이른 메시지 바로 전부터 보수적으로 다시 확인한다. 중복은 암호화 저장소의 방·메시지 ID로 제거한다. 기록을 지운 방의 본문 없는 기준점은 유지해 지운 내용을 되살리지 않는다.
- 재수신한 동일 원문이 정확한 방 제목·작성자 정보를 제공하면 기존 행의 메타데이터만 갱신한다. 말풍선을 중복 추가하거나 계정 화면을 초기화하지 않아 초안과 선택을 유지한다.

## 범위와 근거

전체 80개·최대 7일 보관 한도는 유지한다. 알려지지 않은 모든 방의 전체 이력을 수집하는 변경은 아니다. 읽음 처리·채팅방 입장·자동 발송을 추가하지 않는다. 실제 계정 조회나 발송 대신 가짜 서버·암호화 저장·WPF 회귀 검사로 확인한다.

최종 검사, 적용 파일 해시, 백업 및 대화방 화면 근거는 `exports/spoiler-conversations-20260930/`에 저장한다. 기존 Spoiler는 트레이에서 **완전히 종료**한 뒤 다시 실행해야 새 수신·분류 코드를 사용한다.

## 완료 검증

2026-10-01 원본 소스·실행 파일에 적용했다. Node 115개, 수신 소스 7개, 암호화 저장소 20개, 기존 수신 회귀 14개, 답장 15개, 방 모델 16개 및 WPF UI 92개 검사가 모두 통과했다. 원본 내장 런타임 자체 검사도 통과했고, 테스트한 빌드와 원본 빌드의 컴파일 입력 및 세 런타임 payload가 일치한다.

추가 방 복원은 현재 들어온 메시지뿐 아니라 새 작성자 정보로 확인된 기존 기록도 저장 성공 후 화면에 전달한다. 같은 본문을 다시 받으면 방·메시지 식별자를 검증해 기존 말풍선만 갱신한다. 초기 history 기준점은 실제 본문이 아니므로 빈 페이지에서 저장 진행점으로 쓰지 않으며, 완료된 방만 보호를 해제한다. 부분 조회·저장 실패·중단 시 이전 기준과 보호를 유지한다.

`previews/installed-reference.png`는 전체 리소스를 포함한 검증 빌드의 합성 WPF 화면이다. 실제 계정 로그인, 실제 발송, 상대방의 읽음 수 관측은 하지 않았다. 기존 80개·7일 보관 한도보다 앞의 전체 대화 이력 복구를 보장하는 변경은 아니다.
