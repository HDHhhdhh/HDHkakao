요청한 1·2·3번 개선을 구현하고 KakaoSender 소스 및 Spoiler 원본 소스·실행파일에 적용했다. 실행 중인 앱은 재시작하지 않았다. 실제 계정 로그인, 메시지 발송, 예약 등록은 수행하지 않았다.

이 문서는 앞선 저장 경쟁·수신 배치·첨부 준비 작업의 기록이다. 이후 서버 인증 갱신 조율과 누락된 빌드 입력 복구, 인증 런타임 통일, 책임 분리를 추가했다. 현재 결과는 [후속 보고서](STRUCTURE_IMPROVEMENTS_2026-09-30.md)에 기록한다.

| 개선 | 적용한 동작 | 검증 |
|---|---|---|
| 공용 인증 저장 경쟁 | Python·C#이 같은 파일 잠금을 사용하고, 로그인에 사용한 암호화 파일의 SHA-256 버전이 그대로일 때만 갱신 저장. 충돌하면 저장 ACK를 거절하고 해당 세션을 닫음 | 실제 Windows Python↔C# 잠금·DPAPI·버전 비교, 오래된 토큰의 덮어쓰기 거절, 저장 실패·충돌 뒤 WRITE 차단 |
| Spoiler 수신 저장 | 최대 50건 또는 100ms 동안 모은 메시지를 한 트랜잭션으로 저장. 저장 성공 후 순서대로 알림 전달. 저장 실패 시 묶음 재시도 | 가상 자식 프로세스 120건: 저장 120회→3회, 순서·이름·저장 검사 실패 0. EOF·중단·계정 변경·콜백 예외 검사 |
| 첨부 실행 단위 준비 | 발송 전 원본을 한 번씩 임시 복사. 같은 복사본을 모든 대상 및 연결 복구에 사용. Node의 준비 버퍼는 최대 100 MiB까지 재사용 | 원본 수정·삭제 뒤에도 같은 내용 유지, 잘못된 후속 파일 때문에 첫 발송 전에 중단, 취소·실패 후 임시 파일 정리 |

첨부 원본이 발송 중 수정되면 **실행 시작 때 준비한 내용 유지**를 사용자가 선택했다. 새 실행은 원본을 다시 준비한다. 행당 파일 10개·합계 100 MiB 제한은 유지하며, 복사는 1 MiB 단위다. 실행 전체의 임시 디스크 사용량은 서로 다른 파일 크기의 합계다. 준비 중 파일 변경이나 디스크 쓰기 실패가 발생하면 발송 전에 중단한다.

Node 캐시에서 제거된 파일은 복사본을 다시 읽고 체크섬을 검증한다. 이미지 정보는 재사용한다. 연결 복구로 자식 프로세스가 바뀌면 준비 정보도 다시 만들지만 원본을 다시 읽지는 않는다. 파일 업로드와 대상별 전송은 각각 수행하며, 일부 전송 또는 응답 불명 뒤에는 자동 재전송하지 않는다. 연결 복구 후의 로컬 준비 실패는 미발송으로 기록해 직접 전송 이어하기를 허용한다.

100ms는 메시지를 모으는 대기 기준이며, 저장·스레드 대기·화면 콜백 처리 시간은 별도다. 저장 실패 동안에는 후속 읽기에 역압을 걸어 메모리를 제한한다. 기존 보관 정책은 유지한다.

인증 변경은 **로컬 파일의 오래된 덮어쓰기**를 막는다. 외부 SDK의 서버 OAuth 갱신 요청 전체를 두 앱 간에 직렬화하는 기능은 포함하지 않는다. 충돌한 앱은 새로 저장된 인증 정보로 다시 연결해야 한다. 이전 버전으로 실행 중인 앱은 새 잠금·버전 검사에 참여하지 않으므로 양쪽 앱 재시작이 필요하다.

작업 도중 별도 채팅의 삭제 사고로 기존 파일과 개발 의존성이 사라졌다. Hub 필수 모듈 두 개와 관련 Git 파일은 해당 복구 작업에서 복원됐다. Spoiler의 누락된 CredentialVault.cs는 이번 검토된 수정본으로 적용했다. 일부 Spoiler bridge 개발 의존성은 여전히 누락되어, 이번 실행파일은 앞서 생성·검증한 bridge 번들을 재사용해 빌드했다. 저장소 전체 복구나 의존성 재설치를 완료했다고 주장하지 않는다.
