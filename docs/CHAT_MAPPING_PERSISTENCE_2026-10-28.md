# 부분 조회가 저장 매칭을 삭제하던 오류

## 원인

서버 전체 목록은 일부 방을 누락하거나 상대 확인 정보 없이 반환할 수 있다.
저장된 ID가 빠지고 동명이인 방이 나타나면 매칭 정책은 이를 모호한 결과로 분류한다.
이때 저장 단계가 모호한 요청 이름까지 삭제했다. 다음 조회는 복구할 ID를 잃었다.

저장 대상과 신규 이름이 섞이면 기존 빠른 조회도 비활성화됐다.
전체 목록 조회 실패와 불완전한 목록의 영향을 모든 대상이 받았다.

## 변경

- 모호한 조회는 기존 ID와 확인된 이름을 유지한다. 검증 근거가 없는 잘못된 항목은 계속 제거한다.
- 전송 전 검사는 모호한 결과를 차단한다. 저장된 값이 있다는 이유로 전송을 허용하지 않는다.
- 혼합 명단도 저장 ID부터 서버에서 확인한다. 저장된 일반 이름은 구조화된 CSV 이름의 조회 후보로만 사용한다.
- 신규 이름은 기존 이름·상대 ID·소유권 검사를 통과해야 저장한다. 이름 유사성만으로 승인하지 않는다.
- 전체 목록이 실패해도 같은 요청에서 확인한 저장 ID 결과는 유지한다.
- 추가 조회 실패 코드도 로컬 진단 기록에 남긴다. 메시지 본문과 인증 정보는 기록하지 않는다.

## 검증

실패 당시 목록과 과거 설정으로 저장 매칭 삭제를 재현했다.
누락된 두 이름은 과거 발송 기록 또는 저장 ID를 현재 서버 상대 ID·친구 이름과 대조한 뒤 복구했다.
저장 파일은 백업했다. 기존 213개 매칭을 유지했다.

실제 GUI 조회 함수를 화면 없이 실행한 결과, 대상 35개 모두 확인됐다.
전체 목록 호출 없이 저장 ID 조회로 처리됐으며 조회 작업은 약 4.26초였다.
메시지 전송·읽음 처리·방 입장 요청은 진단용 프로토콜 허용 목록에서 차단했다.
실제 창 조작 및 실제 발송 검사는 하지 않았다.

회귀 검사는 혼합 명단, 전체 목록 실패, 동명이인, 재조회 복구,
저장 후 다시 읽기, 수동 매칭 보호, 모호한 상태의 전송 차단을 다룬다.
개인 이름·ID와 실측 상세 결과는 Git에서 제외된 로컬 진단 폴더에 보관한다.
