추가 개선 제안 중 **1·2·3번은 후속 작업에서 구현·검증·원본 적용을 완료했다.** [후속 결과와 검증 범위](RELIABILITY_IMPROVEMENTS_2026-09-30.md)를 참고한다. 이어서 최초 제안의 **4번 책임 분리·6번 인증 런타임 통일**과 서버 인증 갱신 조율·빌드 복구를 적용했다. [현재 구현 및 검증 결과](STRUCTURE_IMPROVEMENTS_2026-09-30.md)에 기록했다. 아래 목록은 최초 제안의 근거이며, **5번 기간별 수집·CSV 내보내기는 아직 구현하지 않았다.**

1. **공용 인증 writer와 버전 검사.** Spoiler C#와 Sender Python이 같은 `loco-credentials.dat`을 각각 저장한다. 파일 원자 교체만으로 오래된 갱신 응답이 새 토큰을 덮어쓰는 문제를 막을 수 없다. 공용 잠금과 저장 전 버전 비교를 양쪽에 적용하거나 인증 갱신을 한 프로세스가 소유해야 한다. 가장 우선할 안정성 작업이다.
2. **Spoiler 수신 저장의 작은 묶음 commit.** 현재는 메시지마다 전체 inbox를 복제·정렬·암호화·fsync한다. 페이지 또는 짧은 묶음으로 본문·중복 ID·복구 위치를 함께 저장한 뒤 UI에 알려야 한다. 저장 전 성공 처리나 단순 debounce로 바꾸면 누락 위험이 생긴다.
3. **같은 첨부 파일의 실행 단위 준비.** 여러 대상에 같은 PDF·이미지를 보낼 때 파일 읽기·해시·이미지 정보를 매번 계산한다. 실행 시작 시 변경 불가능한 파일 묶음을 한 번 준비하고, 각 대상에는 업로드만 수행하면 반복 작업을 줄일 수 있다. 파일 변경 감지와 용량 상한은 유지한다.
4. **책임이 섞인 큰 파일을 실제 경계에서 분리.** Sender GUI의 매칭 작업·미리보기·실행 표시, Spoiler의 프로세스 관리·프로토콜 파싱·수신 표시를 단계적으로 나눈다. 현재 사용하지 않는 1,115행 MessageCheckpointStore는 cursor DTO를 분리한 뒤 legacy 검사·빌드 참조와 함께 정리한다. Spoiler의 QA 도구도 현재 InboxStore를 검사하도록 맞춰야 한다.
5. **기간별 수집·CSV 내보내기.** 현재 화면의 최근 80개 본문 정책과 날짜 범위 보관을 분리해, 대화명·본문·수신 시각·첨부 종류를 내보내는 기능을 추가할 수 있다. 최근 3일 수집에는 별도 보관 기간과 누락 복구 상태가 필요하다. 읽음 상태를 변경하는 기능은 연결하지 않는다.
6. **인증 런타임 선택 규칙 통일.** Sender는 설치된 runtime의 mtime으로 auth 버전을 선택한다. Spoiler의 manifest·hash 검증 계약을 공유해 사용할 runtime을 명확히 정하고 자식 프로세스 환경도 통일해야 한다.
