# CSV 예약 자동 등록

`kakao_schedule_batch.py`는 Windows 카카오톡의 **공식 예약 메시지 화면을 조작하여 예약을 저장**한다. 등록 후에는 카카오톡 예약 목록에 남는다. 서버 API 직접 호출이나 PC에서 예약 시각까지 기다렸다가 즉시 발송하는 기능은 아니다.

Hub GUI와 `kakao_schedule_batch.py`는 같은 자동 등록 기능과 예약 기록을 사용한다. CSV의 대화명·본문·예약일시를 읽고 입력값을 다시 확인한 뒤 등록하며, 새 접수 완료 알림으로 등록을 확인한다. 기본 등록 과정에서는 예약 목록을 열거나 읽지 않는다. Codex·LLM·API 키 없이 실행된다. 현재 텍스트 예약만 지원한다.

## Hub GUI

`예약일시`가 있는 CSV/XLSX를 불러오고 발송을 시작한다. 행별 수동 내용 확인이나 검색창 좌표 설정은 필요하지 않다. 공통 예약 시각도 사용할 수 있다. 직접 전송 ON/OFF에 관계없이 예약은 카카오톡 화면으로 등록한다.

설정 탭의 예약 카운터는 `예약 추정 54/100 · 여유 46개`처럼 Hub/CLI의 등록 기록과 현재 PC 시각으로 계산한 수량을 표시한다. 매초 다시 계산하며 `예약 기록 새로 계산`도 화면 조작 없이 동작한다. CSV를 불러오기만 한 행과 제출 전 중단된 행은 세지 않는다. 새 접수가 확인된 행, 이전에 상세를 확인한 행, 제출 결과가 불명확한 행과 진행 중 확보한 슬롯을 예약 시각까지 세며 같은 예약을 중복으로 세지 않는다. 신청 건수가 여유보다 많으면 첫 등록 전에 전체 묶음을 중단한다. 매 행의 슬롯 확보도 공용 기록의 잠금으로 조율한다.

카운터와 중복 방지 기록은 `%LOCALAPPDATA%\KakaoSender\schedule\reservations.sqlite3`에 저장되어 재시작 후 유지된다. 예약 시각에 도달한 행은 슬롯 계산에서 제외하고 새 예약에 그 여유를 사용한다. **시간 경과는 실제 발송·수신 완료 확인이 아니다.** 기존 접수·결과 불명 기록은 그대로 보존해 동일 행의 재등록을 막는다. 예전 카운터의 실제 목록 관측값은 등록 기록 기반 계산으로 자동 전환한다. 빈 기록은 0건으로 계산하지만 손상된 기록은 임의로 비우지 않는다.

이 카운터는 같은 기록 파일을 사용하는 Hub/CLI의 예약만 추적한다. PC 카카오톡이나 다른 기기에서 직접 추가·삭제한 예약과 서버의 발송 지연은 반영하지 않는다. 따라서 카카오톡 실제 목록의 수량과 다를 수 있다. 수량 확인을 위한 예약 목록 OCR 때문에 등록이 중단되는 과정은 제거했다.

## 실행

카카오톡에 로그인된 Windows 데스크톱에서 실행한다. 등록 중에는 마우스·키보드를 자동화가 사용한다. 예약 시각은 5분 단위이고 실행 시각에서 최소 5분 이후여야 한다.

```powershell
python kakao_schedule_batch.py --csv messages.csv --output exports/schedule-run --submit
```

`--submit`을 빼면 첫 미등록 행의 양식을 채우고 멈추며 실제 등록하지 않는다. `--limit 1`을 추가하면 한 행만 처리한다. CSV 열은 기존 KakaoSender의 `chat_name`, `text`, `scheduled_at` 형식을 사용한다.

등록 중 중단되어 예약 양식이 남아 있으면 같은 입력으로 재실행한다. 현재 양식의 실제 대상·본문이 이번 CSV와 정확히 일치할 때만 그 초안을 정리한다. 초안 정리는 이미 저장된 예약을 삭제하지 않는다. 접수가 확인된 행은 다시 등록하지 않는다. 이전 제출 결과가 불명확한 행은 해당 행만 `예약 확인 필요`로 보류하고 다른 미등록 행은 계속 처리한다. 그 행의 접수 여부는 사용자가 확인해야 한다. 현재 실행 중 새 제출 결과가 불명확해지면 후속 입력은 중단한다. CLI는 보류 행이 남으면 종료 코드 2를 반환하고 `status.json`에 해당 상태를 남긴다. Esc, GUI의 중단 버튼 또는 화면 모서리로 마우스를 이동하면 자동화가 멈춘다. `--resume-form`은 준비 전용 실행에서 기존 초안을 이어서 확인할 때 쓴다.

작성 취소 확인창까지 남아 있으면 소유 관계와 실제 안내 문구를 확인한 뒤 `취소`로 입력 화면을 복구한다. 그 다음 화면을 앞으로 올려 대상·본문을 대조한다. CSV와 일치하지 않는 초안은 버리지 않고 중단한다. 다른 프로그램의 팝업에 가려진 화면을 예약 값으로 사용하지 않는다.

초안 정리에서는 대화명과 전체 본문만 읽는다. 아직 설정하지 않은 날짜·시간의 OCR 오류 때문에 정리가 막히지 않는다. 실제 등록 전에는 날짜·오전/오후·시간과 본문을 모두 검증한다.

GUI에서 이미 접수된 행을 다시 실행하면 `기존 예약 유지`로 기록한다. 기존 접수 결과를 읽으며, 새 등록 시도로 기록하거나 등록 버튼을 누르지 않는다. 결과가 불명확한 행은 계속 보류한다.

**같은 예약에는 항상 같은 저널 파일을 사용한다.** 기본 경로는 GUI와 공유한다. `--journal`을 지정하면 별도 기록을 사용한다. 파일을 새로 만들거나 삭제하면 기존 등록의 중복 방지 기록을 잃는다. 이미 접수됐거나 제출 여부가 불명확한 행은 자동으로 다시 등록하지 않는다.

## 결과 확인

```powershell
python kakao_schedule_batch.py --csv messages.csv --output exports/schedule-run --status
python kakao_schedule_batch.py --csv messages.csv --output exports/schedule-run --verify-only
```

`--status`는 로컬 기록만 읽는다. `--verify-only`는 사용자가 명시적으로 실행할 때만 예약 목록의 상세를 열어 대상·시각·전체 본문을 원문과 비교한다. 기본 등록 과정에서 호출하지 않는다. 새 예약을 만들거나 저장·삭제 버튼을 누르지 않는다. 결과는 `status.json`, 검증이 모두 끝나면 `list-audit.json`에 저장된다.

| 상태 | 의미 |
|---|---|
| `prepared` | 아직 등록을 시도하지 않음 |
| `rejected_before_submit` | 등록 버튼을 누르기 전에 중단됨. 양식을 확인하고 재개 가능 |
| `cancelled_by_user` | 사용자가 실제 예약 목록에서 취소했다고 명시적으로 확인한 행. 이전 제출 이력을 보존하고 재등록 가능 |
| `submitting` / `unknown` | 제출 가능성이 있어 재등록 차단. 예약 목록에서 먼저 확인 필요 |
| `acknowledged` | 새 접수 완료 토스트 확인. 재등록 차단 |
| `verified` | 저장된 예약 상세의 대상·시각·전체 본문까지 원문 일치 확인 |

`verified`는 예약 저장 검증이며 미래의 실제 발송·수신 완료를 뜻하지 않는다. 접수 여부가 불명확한데 목록 대조로도 확인되지 않으면 코드가 멈춘다. 저널을 지우고 재시도하지 않는다.

사용자가 카카오톡의 예약 목록을 직접 비운 경우에는 자동으로 알 수 없으므로 취소 사실을 별도로 반영해야 한다. `scripts/reconcile_schedule_cancellations.py`는 명시적인 취소 확인과 원본 기록의 스냅샷을 요구하는 관리 도구다. 확인한 미래 예약만 `cancelled_by_user`로 바꾸고 그 행의 슬롯을 해제한다. 과거 예약·새 제출·변경된 기록은 초기화하지 않는다. 기본 등록 과정에서는 호출하지 않는다.

## 관측 기록과 대응

- 실제 창의 PID·제목·위치·포커스와 입력 대상 컨트롤을 확인한다.
- 대화 검색에는 확인된 검색 Edit를 사용한다. 카카오톡의 전역 단축키로 동작했던 `Ctrl+A`는 사용하지 않는다.
- 물리 해상도 화면을 저장하고 대상·날짜·시간을 분리해 OCR로 판독한다. 작은 한글의 배율 오류는 원본/확대 판독과 명암 변환 결과를 비교한다. 예상 이름으로 OCR 글자를 치환하지 않는다.
- 한글 이름이 여러 배율에서 같은 다른 글자로 읽히면, 관측된 글자 픽셀을 유지한 채 빈 열의 간격만 바꾼 두 화면을 다시 판독한다. 두 결과 모두 전체 대화명과 정확히 일치해야 진행하며, 판독 좌표는 원본 화면으로 되돌린다.
- 좁은 오전/오후 메뉴에서 목표 항목이 누락되면 같은 저장 화면을 3배율로 다시 판독한다. 실제로 읽힌 정확한 항목의 좌표로만 선택하며, 메뉴 순서로 값을 추측하지 않는다.
- 시각 메뉴의 순서는 `12, 1, …, 11`이므로 실제로 읽은 항목의 순위로 스크롤 방향을 정한다. 메뉴 경계에서 일부만 보이는 숫자는 선택 대상에서 제외한다. 온전히 보이는 세 행 이상의 높이·간격과 경계 위치를 확인할 수 있을 때만 잘린 경계 행을 제외하고, 목표 숫자가 온전히 보일 때까지 다시 관측한다.
- 첫 OCR에서 목표 숫자를 읽은 경우에도 같은 저장 이미지에서 온전한 문자 행의 위치를 검사한다. 잘린 숫자의 일부가 목표 숫자로 읽혀도 그 좌표를 누르지 않는다. OCR 좌표와 원본 이미지의 크기가 다르면 중단한다.
- 사람이 실제 이름 화면을 확인한 교정 자료는 `native_schedule_recipient_samples.json`과 원본 이름 이미지로 보존한다. 현재 이름 영역 전체의 크기·픽셀 해시·픽셀이 원본과 모두 같고 확인한 이름도 CSV와 일치할 때만 재사용한다. 글자 치환이나 비슷한 이름 매칭은 하지 않으며, 다른 픽셀이면 일반 OCR로 검증한다.
- 대상 창·좌표·겹침 검사를 통과한 뒤 실제 등록 클릭 직전에 저널을 먼저 기록한다. 클릭 전 검사 실패는 미제출로 남아 다시 진행할 수 있다. 실제 클릭을 시도한 후 응답을 놓치면 해당 행은 다시 제출하지 않는다.
- 예약창이 닫힌 직후 접수 알림이 아직 없으면 최대 5초 동안 새 화면을 관측한다. 알림이 확인되면 바로 다음 행으로 진행하며 매 행마다 5초를 기다리지는 않는다. 대기 중에는 등록 버튼을 다시 누르지 않고, 정확한 접수 문구가 끝내 확인되지 않으면 결과 불명으로 남긴다. 각 화면과 판독·대기 시간은 로그에 저장한다.
- 서버 응답으로 등록창이 늦게 닫히는 경우에는 최대 10초까지 닫힘을 기다린다. 창이 닫히면 즉시 접수 판독으로 넘어가며 추가 클릭은 하지 않는다. 끝내 남아 있는 창은 화면을 저장하고 결과 불명으로 중단한다.
- 접수가 확인된 다음에는 그 행의 대상 채팅방을 활성화해 Esc로 닫고, 닫힘 확인 후 다음 행을 처리한다. 메인 창·예약창·다른 채팅방에는 Esc를 보내지 않는다. 자동화가 보낸 Esc는 사용자 중단으로 오인하지 않으며, 창 정리 실패 시 접수 성공 기록을 유지하고 후속 입력을 중단한다.
- 반투명 접수 알림에 배경 대화 글자가 섞여 판독되면, 실제 검은 알림 테두리 안의 밝은 글자 픽셀만 분리한 화면으로 다시 판독한다. 예상 문구를 이미지에 그리거나 OCR 글자를 치환하지 않으며, 재판독도 정확한 접수 문구가 확인돼야 성공으로 남긴다.
- 채팅방을 넓히거나 높여도 접수 알림의 글자와 바탕 크기는 함께 확대되지 않는다. 알림은 연속된 검은 바탕으로 찾고, 창 전체 비율에 따른 최소 크기를 제한해 서로 다른 채팅방 크기에서도 확인한다.
- `events.jsonl`에는 실제 조작, 판독 결과, 중단 이유와 화면 경로가 남는다. 캡처에는 메시지 본문과 대화명이 포함되므로 외부에 공유할 때 내용을 확인한다.
- 이번 화면에서 검증된 레이아웃과 다른 카카오톡 버전·크기에서는 판독 또는 창 검증 실패 시 중단한다.
