# HDHkakao의 목표와 개발 기록

HDHkakao는 사용자가 카카오톡 업무를 덜 반복하고, 작업 결과를 믿을 수 있게 만들려는 프로젝트다. Spoiler는 대화를 읽고 답장한다. KakaoSender는 명단에 맞춰 메시지를 보내고 예약을 등록한다.

이 기록은 **2026-10-10의 소스와 당시 확인할 수 있는 세션 기록**을 기준으로 작성했다. 기능의 존재, 실제 시험 결과, 앞으로 원하는 기능을 구분한다.

## 기록을 다시 확인한 범위

다음 관련 대화 4개를 페이지 끝까지 조회했다. 반환된 사용자 메시지와 작업 결과를 읽고, 프로젝트에 남은 보고서·검증 자료·현재 소스와 대조했다.

| 대화 | 이번 문서에서 사용한 내용 |
|---|---|
| 이전 **카카오톡 Hub** | 초기 화면 발송, 예약 입력, 직접 통신 도입, 자동 매칭, 예약 프로토콜 조사 |
| 현재 **카카오톡 Hub** | 2.4 개선부터 실제 대량 발송 사고, 예약 54건, 두 앱의 리팩토링, 최신 UI·속도 패치까지 |
| **확인 카카오톡 메시지 직접 읽기** | Spoiler의 최초 목적, 알림 수집 실패, 태블릿 직접 수신, 복구·저장·계정 분리 |
| **카카오센더 예약 메시지 CSV 만들기** | 학생 이름을 실제 대화명으로 바꾼 과정, 시험일 기준 예약 행 생성과 주간 분할의 배경 |

대화 조회 결과의 일부 초기 항목에는 작업 시각이 없었다. 해당 단계에는 임의의 날짜를 붙이지 않았다. 옛 답변의 ‘완료’ 문구만으로 해결을 인정하지 않았다. 후속 오류가 나온 경우에는 실패와 추가 수정까지 함께 기록했다.

이번 문서 작업에서 실제 카카오톡 예약 목록을 조회하거나 메시지를 보내지는 않았다. 과거 화면과 서버 시험의 결과를 새로 실행한 결과처럼 쓰지 않았다.

## 개발 과정에서 정한 기준

```mermaid
flowchart LR
    A[사용자 요구] --> B[실패 기록]
    B --> C[원인 확인]
    C --> D[코드 수정]
    D --> E[범위에 맞는 검사]
    E --> F[확인한 결과와 남은 한계]
    F --> B
```

같은 요구라도 한 번의 성공으로 끝내지 않았다. 실제 실패가 나오면 기존 가정을 다시 확인했다. 이 문서는 그 반복 과정에서 남은 설계 기준을 설명한다.

## 공개 이력의 경계

공개 저장소의 첫 커밋은 `88d20039f594d1b4fedc79e5fd5412317885ad92`다. 이 커밋은 두 프로그램의 당시 소스를 모은 시작점이다. 초기부터의 모든 Git 커밋이 이어진 이력은 아니다. 여기의 날짜별 설명은 세션과 저장된 증거에서 재구성한 개발 기록이다.

원본 대화, 학생·보호자 명단, 계정 정보, 예약 CSV, 실계정 로그와 화면은 공개하지 않는다. 개인 이름 화면을 사용한 OCR 교정 자료도 로컬에만 남긴다. 문서에는 익명화한 증상, 집계 수치, 공개 소스와 테스트 위치를 남긴다.
