# Spoiler

Spoiler는 카카오톡 계정에 **태블릿 보조기기**로 별도 연결해, 연결 이후 서버에서 도착하는 새 메시지를 작은 Windows 앱에 표시합니다. Windows 알림 팝업, OCR, PC 카카오톡 화면, 로컬 채팅 DB를 사용하지 않습니다.

## 처음 연결하기

1. `Spoiler`를 실행하면 `태블릿 보조기기 연결` 창이 열립니다.
2. 그 창에 카카오계정 이메일과 비밀번호를 입력합니다. 비밀번호는 등록 프로세스의 메모리로 한 번 전달되며 저장하거나 로그로 남기지 않습니다.
3. 확인 코드가 보이면 휴대폰 카카오톡에서 새 기기 등록을 승인합니다.
4. 기존 태블릿 슬롯이 사용 중이면 `기존 태블릿 연결 바꾸기`를 직접 눌러야만 교체가 진행됩니다. PC 카카오톡 슬롯은 사용하지 않습니다.
5. 등록 후에는 카카오톡 알림 팝업을 꺼 둬도 새 메시지가 Spoiler에 표시됩니다.

`F5` 또는 `다시 연결`은 태블릿 세션을 재연결합니다. `태블릿 설정`은 등록을 다시 진행합니다. `Ctrl+Shift+Delete`는 확인 후 Spoiler의 로컬 메시지 기록만 지우며 카카오톡 대화에는 영향을 주지 않습니다.

Spoiler는 최근 메시지를 받은 대화방의 마지막 서버 `logId`를 계정별 암호화 상태로 기억합니다. 앱이 종료됐거나 연결이 끊긴 동안 생긴 공백은 다음 연결 때 방별로 최대 50개씩 읽기 전용 이력 조회로 보완합니다. 페이지를 순차로 확인하고 방별 진행점을 저장합니다. 시간·처리 한도를 넘으면 `일부 복구`가 표시되며 다음 연결에서 저장된 지점부터 이어집니다. 한 번도 메시지를 받은 적 없는 방이나 7일을 넘긴 공백은 복구 기준점이 없을 수 있습니다.

메시지는 **대화방 기준**으로 묶입니다. 왼쪽에서 방을 선택하면 오른쪽에 작성자·시각·원문 말풍선이 시간순으로 나타납니다. 받은 메시지는 흰색, 내 메시지는 노란색입니다. 말풍선의 텍스트는 선택·복사할 수 있으며 줄바꿈과 장문을 그대로 표시합니다. 방 목록은 최근 메시지 순으로 정렬되지만 새 메시지가 와도 선택한 방과 읽던 스크롤 위치를 유지합니다. 맨 아래에서 읽고 있으면 새 메시지를 따라갑니다.

`대화방 · 내용 검색`, `내 메시지 포함`, `시각 찾기`는 보관된 기록만 필터링합니다. 방 옆의 `N개`는 **로컬 보관 수**이며 카카오톡의 서버 안읽음 수가 아닙니다. 보관 한도는 전체 1,000개·최대 7일입니다. 이전 형식의 기록도 표시하지만, 대화방 ID가 없는 기록은 안전하게 읽기 전용으로 남깁니다.

이전 버전의 작성자별 그룹도 같은 계정의 암호화 메타데이터에 남은 실제 방·작성자 ID로 정확히 확인되면 대화방별로 자동 재분류합니다. 이름만 같은 기록을 합치지 않습니다. 확인할 수 없는 내용은 `방 미확인 이전 기록`으로 따로 표시하며 답장할 수 없습니다. 내 메시지 포함은 기본으로 켜져 있고, 단톡방에서도 내·여러 상대의 메시지를 서버 시각과 메시지 ID 순으로 함께 보여줍니다.

연결 중에는 알려진 방의 내역을 읽기 전용으로 보충해 다른 기기에서 보낸 내 메시지의 수신 누락도 보완합니다. 실시간 최신 로그로 동기화 위치를 건너뛰지 않으며, 재접속 때 보관된 가장 이른 메시지부터 다시 확인합니다. 암호화된 중복 방지 ID와 기록 삭제 기준점은 유지합니다.

## 직접 답장

선택한 방에 답장을 입력하고 `전송` 또는 `Ctrl+Enter`를 누르면 연결된 태블릿 세션이 서버에 직접 텍스트를 전송합니다. `Enter`는 줄바꿈입니다. AI 답장은 이번 버전에 포함되지 않습니다. 방마다 초안을 유지하며 방 선택·검색·입력만으로 전송하지 않습니다. 연결 준비 전, 방 ID가 없는 기록, 공백만 있는 본문, 다른 계정으로 전환 중에는 보내지 않습니다. 본문은 최대 4,000 UTF-16 문자입니다.

서버의 방·메시지 ID·시각이 유효하고 해당 원문이 암호화 보관소에 저장된 뒤에만 성공으로 표시하고 변경되지 않은 초안을 비웁니다. 전송 중 중복 클릭을 차단합니다. 실패 또는 응답 불명확 시에는 초안을 유지하고 자동 재전송하지 않습니다. 결과 불명 상태에서는 실제 대화를 확인한 뒤 다시 보낼지 결정해 주세요. 송신 도중 새로 작성한 초안이나 다른 방의 초안은 이전 전송 결과로 지우지 않습니다.

## 읽음 상태와 안전 범위

- Spoiler의 수신 경로는 `MSG` 이벤트만 구독하며 메시지 전송, 채팅방 열기, `NOTIREAD`/읽음 워터마크 호출을 노출하거나 실행하지 않습니다.
- 재접속 복구는 SDK의 읽기 전용 `getMessagePage`/`MCHATLOGS` 경로만 사용합니다. 채팅방에 들어가는 `CHATONROOM`이나 읽음 처리 `markRead`는 브리지 facade에 노출하지 않습니다.
- 연결 자체는 카카오 서버에 로그인한 활성 태블릿 보조기기로 보이며 연결 유지를 위한 세션 통신을 합니다.
- Spoiler로 메시지를 받는 것만으로 상대방 화면의 `1`을 지우는 호출은 하지 않습니다. 다만 휴대폰, PC 카카오톡, 다른 기기에서 같은 채팅방을 읽으면 `1`은 정상적으로 사라집니다.
- 카카오계정 비밀번호는 저장하지 않습니다. 액세스 토큰·리프레시 토큰·태블릿 UUID는 현재 Windows 사용자만 해제할 수 있는 DPAPI로 `%LOCALAPPDATA%\Spoiler\loco-credentials.dat`와 `loco-device.dat`에 보관합니다.
- 본문·중복 방지 ID·방별 복구 기준점·이름 캐시를 계정별 DPAPI 파일 `%LOCALAPPDATA%\Spoiler\inbox-<계정 해시>.dat`에 함께 저장합니다. 본문 저장이 성공해야 처리 완료로 확정되며, 실패하면 해당 이벤트를 보류하고 재시도합니다.
- 화면 본문은 **서버 시각 기준 최신 1,000개, 최대 7일**만 보관합니다. 7일간의 모든 메시지를 보관하는 프로그램은 아닙니다. 앱이 켜져 있는 동안에도 만료 기록을 정리합니다.
- 이전 버전의 `history.dat`와 `message-checkpoint.dat`는 소유 계정을 검증할 수 없어 자동으로 불러오거나 새 계정에 귀속시키지 않습니다. 기존 암호화 파일은 보존하며, `기록 지우기`를 선택하면 이전 본문 파일과 임시파일도 지웁니다. 삭제 후 재수신으로 같은 본문이 되살아나지 않도록 처리 ID·복구 기준점은 유지합니다.
- 만료 토큰을 갱신할 때는 새 토큰을 DPAPI로 원자적으로 저장했다는 Windows 호스트의 확인을 받은 뒤에만 다시 사용합니다.

## 알아둘 점

이 연결은 카카오가 공개한 개인 채팅 수신 API가 아니라, 공개된 비공식 LOCO 구현인 `agent-messenger@2.37.1`을 제한된 읽기 전용 경계 뒤에서 사용합니다. 카카오가 제공하거나 보증하는 앱이 아니며, 서버 정책이나 프로토콜 변경으로 연결이 중단될 수 있습니다.

태블릿 슬롯을 교체하면 예전에 쓰던 실제 태블릿 카카오톡 세션은 종료될 수 있습니다. 이후 실제 태블릿으로 다시 로그인하면 Spoiler 세션이 종료될 수 있습니다. 토큰은 계정 접근 권한이 큰 민감 정보이므로 Windows 계정을 다른 사람과 공유하지 마세요.

대화명은 메시지에 포함된 이름을 우선 사용하고, 누락되면 계정별 로컬 이름 캐시와 서버의 읽기 전용 멤버/방 제목 정보로 보완합니다. PC 카카오톡 주소록에만 저장된 사용자 지정 별칭은 서버가 태블릿 세션에 제공하지 않으므로 Spoiler에서 정확히 그대로 표시할 수 없습니다.

사진·동영상·음성·파일처럼 본문이 비어 있는 이벤트는 자동 다운로드하거나 채팅방을 열지 않고 `[사진]`, `[파일]` 같은 종류만 표시합니다.

직접 답장은 수신 경로와 분리된 명시적 WRITE 요청입니다. SDK의 재접속 자동 재시도를 거치는 송신 API 대신 한 번의 세션 WRITE와 원본 서버 응답 검증을 사용합니다. 답장 코드 역시 `markRead`/`NOTIREAD`/`CHATONROOM`을 호출하지 않지만, **답장 송신 후에도 상대방의 ‘1’이 그대로 유지된다는 실측 보장은 하지 않습니다**. 핵심 읽기 동작과 직접 송신은 구분됩니다.

## 단일 파일 배포

완성된 `Spoiler.exe` 하나만 다른 Windows PC에 복사하면 됩니다. Node.js와 수신·명시 답장 브리지 및 인증 브리지가 EXE 안에 내장되어 있어, 받는 사람은 Node.js나 보조 폴더를 따로 설치할 필요가 없습니다. 계정 인증은 각 PC에서 별도로 진행합니다.

첫 실행 때 내장 구성 요소를 `%LOCALAPPDATA%\Spoiler\runtime` 아래 버전별 캐시에 풀어 씁니다. 각 파일은 EXE에 내장된 크기·SHA-256 목록과 대조하고, 검증을 통과한 파일만 실행합니다. 검증 후 같은 폴더의 `active-runtime.manifest`에 사용할 버전을 기록하며, KakaoSender도 이 목록과 파일 해시를 확인해 인증 런타임을 선택합니다. 업데이트 후 Spoiler를 한 번 다시 실행하면 새 버전이 적용됩니다. 이 캐시는 배포할 때 함께 보낼 필요가 없습니다.

배포본은 코드 서명이 되어 있지 않으므로 다른 PC에서는 Windows SmartScreen 안내가 나타날 수 있습니다.

## 빌드

빌드하는 PC에만 `tools/runtime-lock.json`에 기록된 Windows x64 Node.js v24.19.0 및 Windows .NET Framework 개발 구성요소가 필요합니다. 빌드는 Node 바이너리 SHA-256이 잠금 파일과 다르면 중단합니다. 다른 위치의 동일 바이너리는 `-NodeExecutable`로 지정할 수 있습니다. 결과물은 내장 런타임을 포함한 단일 `build\Spoiler.exe`입니다.

```powershell
.\build.ps1 -RestoreDependencies
# 이후 의존성을 다시 설치하지 않고 빌드할 때:
.\build.ps1
```

고정 의존성은 `agent-messenger@2.37.1`과 `esbuild@0.28.2`이며 정확한 버전은 `bridge/package-lock.json`에 기록돼 있습니다. 빌드는 현재 소스에서 브리지를 새로 만들고 실행파일의 내장 런타임을 검사합니다. 입력 파일과 결과물 해시는 `build/build-provenance.json`에 기록됩니다.


## 1.3 운영 개선

- 연결 종료 후 남는 프로세스 정리, 자동 재연결, heartbeat 응답 감시, 등록·인증 저장 확인·이력 조회의 제한시간을 적용합니다.
- 연결 초기 단계의 끊어진 소켓은 정상 연결로 채택하지 않습니다. SDK의 보조 동기화 캐시는 원자적으로 저장하며, 깨진 해당 기기 캐시만 원본을 보존해 격리하고 다시 만듭니다. 이 캐시는 로그인 동기화용 ID 정보이며 메시지 본문·계정 인증 저장소와 별개입니다.
- 메시지 갱신은 100ms 단위로 묶고, 숨긴 창은 다시 열 때 렌더링합니다. 긴 단일 메시지와 여러 메시지는 선택한 대화방의 말풍선으로 전문을 확인할 수 있습니다.
- 시간 검색에서 오전/오후를 바꾸는 것은 입력 편집입니다. `찾기`로 확정한 조건과 검색 결과는 다음 검색 실행 전까지 유지됩니다. 오늘 이전 메시지는 날짜도 표시합니다.
- 운영 실행은 QA 로그·스크린샷 환경변수를 무시하며, 오류 문구에는 서버 예외나 토큰 원문을 표시하지 않습니다.
- 현재 PC는 Windows 로그인 시 실행되도록 시작프로그램 바로가기가 등록되어 있습니다. 배포한 EXE가 다른 PC의 시작프로그램을 임의로 등록하지는 않습니다. 별도 등록은 `scripts/Register-Startup.ps1`을 사용합니다.

비공식 서버 연결의 지속 동작이나 모든 미수신 메시지의 완전 복구를 보장하지 않습니다. 상대방 화면의 읽음 상태는 다른 카카오톡 기기 사용에도 영향을 받습니다.

2026-10-06부터 접속 동기화에 남은 방 ID와 새 메시지에서 확인한 방 ID도 읽기 전용으로 점검합니다. 처음 수집하는 방에 최근 7일 이내의 안읽은 메시지가 있으면 서버의 기존 읽음 기준점부터 내역을 보완합니다. 로그인 동기화 결과에 마지막 메시지와 안읽음 수가 빠진 경우에는 마지막 본문 1건을 읽기 전용으로 조회해 시각을 확인합니다. 새 방의 복구 범위는 본문 처리 전에 계정별 암호화 기록에 따로 저장합니다. 재시작해도 미완료 범위를 이어서 처리하며, 사용자가 로컬 기록을 지운 범위는 다시 복원하지 않습니다. 본문 보관 한도는 전체 1,000개이며, 복구 대상 방과 기준점은 별도의 최대 512개 한도로 관리합니다. 메타데이터 조회는 회차당 64개, 내역 처리는 회차당 500개 및 제한시간 안에서 진행합니다. 모든 방의 전체 과거 내역 수집 기능은 아닙니다.
